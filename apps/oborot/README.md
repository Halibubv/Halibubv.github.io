# ОБОРОТ — веб-приложение автосервиса

Демо-проект для портфолио: компания вымышленная, цены примерные.
Из статичного лендинга сделано полноценное приложение: запись на сервис сохраняется в базе,
у клиента есть личный кабинет, у сервиса — админка для записей, расписания и прайса.
Техническое задание: [`docs/tz-oborot.md`](../../docs/tz-oborot.md).

## Что умеет

**Лендинг** (`/`, статичный `public/index.html`)
- Прайс, марки и коэффициенты кузова приходят из базы (`GET /api/catalog`). Если сервер недоступен —
  сообщение «Не удалось загрузить прайс» вместо пустого калькулятора.
- Свободное время на 14 дней вперёд (`GET /api/slots`): слот занят, если на всё время работ нет свободного поста;
  прошедшее время и работы, которые не успеют до закрытия, недоступны.
- Запись (`POST /api/bookings`): цену и длительность считает сервер по тем же правилам, что калькулятор.
  В ответ — номер записи и итог.
- В шапке «Войти» / «Кабинет» / «Админка». Вошедшему клиенту форма подставляет имя и телефон
  и предлагает машину из гаража.

**Кабинет клиента** (`/account`)
- Мои записи: ближайшие и прошлые, статус, услуги, сумма. Отмена записи «новая» или «подтверждена»
  не позже чем за 2 часа до начала.
- Гараж: марка, модель, кузов, год, госномер. Машину с будущими записями удалить нельзя.
- Профиль: имя, телефон, смена пароля с текущим паролем.

**Админка** (`/admin`)
- Сводка: записи на сегодня, число новых, загрузка постов на сегодня и завтра, сумма выполненных за 7 дней.
- Записи: фильтры по дате, статусу, поиск по имени и цифрам телефона; карточка записи с ценами
  на момент записи и историей статусов. Переходы статусов только допустимые
  (новая → подтверждена → в работе → выполнена; отменена; не приехал).
- Расписание: день по постам, сетка «время × пост».
- Прайс: добавить, изменить, скрыть услугу; удалить можно только услугу, которой нет в записях.
- Клиенты: имя, email, телефон, число записей, последняя запись, роль.
- Настройки: число постов, часы работы, марки (премиум или нет).

**Безопасность**
- Пароли — `password_hash` (bcrypt), сессия PHP в cookie `oborot_session` (HttpOnly, SameSite=Lax, Secure на HTTPS).
- Лимит входа: 5 неудачных попыток на пару email + IP и 20 на IP за 15 минут (дальше 429).
- Все запросы на изменение — только JSON, иначе 415.
- Гостю кабинет недоступен (401), клиенту админка (403); клиент видит только свои записи и машины (чужие — 404).
- Запись на последний пост выполняется в транзакции с блокировкой (`SELECT … FOR UPDATE`),
  два одновременных запроса не займут один пост.
- Необязательные уведомления о новых записях в Telegram (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`):
  таймаут 3 секунды, ошибка Telegram не ломает запись.

## Стек

- Сервер: PHP 8.4 без фреймворка, PDO + подготовленные запросы, MySQL 8 (utf8mb4).
- Кабинет и админка: React 19 + React Router 7 + Vite, без UI-библиотек, в стиле лендинга
  (бумага `#eceae4`, красный `#ff3b0a`, Oswald + Manrope + JetBrains Mono).
- Docker: Node собирает интерфейс, итоговый образ — `php:8.4-cli` с `pdo_mysql`.

```
backend/      PHP: config, database, http, validation, auth, catalog (цены), slots (расписание),
              bookings, garage, profile, admin, telegram; bootstrap.php подключает всё
database/     миграции 001-…sql, migrate.php (создаёт базу DB_NAME), seed-demo.php (демо-данные)
public/       index.php — маршруты API; index.html + img/ — лендинг; app.js, app.css — связь лендинга с API
              ui/ — сборка кабинета и админки (npm run build, в Git не хранится)
src/          React: App.jsx (защита маршрутов), api.js, pages/account/*, pages/admin/*
router.php    для встроенного сервера PHP; start.sh — запуск в контейнере
```

## Локальный запуск

Нужны PHP 8.4 с `pdo_mysql`, MySQL 8, Node 22+.

```sh
cp .env.example .env          # впишите DB_USER / DB_PASSWORD, APP_ENV=development
npm install
npm run build                 # интерфейс в public/ui
php database/migrate.php      # создаст базу oborot и таблицы
php database/seed-demo.php    # демо-аккаунты и записи на ближайшие дни
php -S 127.0.0.1:8091 -t public router.php
```

Сайт: http://127.0.0.1:8091/ . Для разработки интерфейса с горячей перезагрузкой — `npm run dev`
(порт 5181, запросы `/api` идут к PHP на 8091). Открывайте http://127.0.0.1:5181/ui/ — React сам перейдёт на /login; после перезагрузки страницы снова заходите через /ui/.

## Демо-логины

| Роль | Email | Пароль |
|---|---|---|
| Клиент | `client@oborot.demo` | `OborotClient2026` |
| Администратор | `admin@oborot.demo` | `OborotAdmin2026` |

Администратор с этим паролем создаётся только при `APP_ENV=development` или `DEMO_MODE=1`.
При `DEMO_MODE=1` логины показаны на странице входа, а в админке можно менять только статусы записей:
прайс, марки, настройки и роли сервер не даст изменить (403). Пароль демо-аккаунтов на демо сменить нельзя.
Все демо-записи и аккаунты помечены в интерфейсе меткой «демо».

## Деплой: Render + Aiven

Blueprint — общий [`render.yaml`](../../render.yaml) в корне репозитория (сервис `oborot`, `rootDir: apps/oborot`,
проверка `/api/health`). Порядок:

1. В Aiven создать бесплатный MySQL, скопировать Service URI и CA-сертификат.
2. В Render: New → Blueprint, указать репозиторий. Для `oborot` ввести `DATABASE_URL` (Service URI)
   и `DB_SSL_CA` (текст `ca.pem`). `DB_NAME=oborot`, `DEMO_MODE=1`, `RESET_DEMO=1` уже заданы в blueprint.
3. При запуске контейнер поднимает сервер на `$PORT`, создаёт базу `oborot` (если её нет), выполняет миграции
   и пересоздаёт демо-данные со свежими датами (`RESET_DEMO=1`).

Необязательно: `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` — уведомления о новых записях.
