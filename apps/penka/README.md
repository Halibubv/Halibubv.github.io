# Пенка — веб-приложение кофейни

Демо-проект для портфолио: кофейня «Пенка» вымышленная, адрес, меню и цены условные.
Было — статичный лендинг. Стало — приложение, где **гости бронируют столик и заказывают
с собой сами, а кофейня видит всё в одном окне**. ТЗ: [`docs/tz-penka.md`](../../docs/tz-penka.md).

## Что умеет

**Сайт (лендинг на `/`)**

- Меню из базы: категории, цены, объём, метки «хит» и «веган». Позиции из стоп-листа видны,
  но помечены «нет в наличии» и не добавляются в заказ.
- Заказ с собой: кнопка «+» у позиции, выезжающая корзина (хранится в `localStorage`),
  время готовности — сегодня или завтра, в часы работы, не раньше чем через 15 минут, шаг 15 минут.
  Цены и сумму считает сервер. Оплата при получении, онлайн-оплаты нет.
- Бронь столика: день (14 дней вперёд), свободное время с сервера (каждые 30 минут, последняя
  бронь за 1,5 часа до закрытия), 1–8 гостей. Сервер сам выбирает самый маленький свободный
  столик, куда все поместятся. Бронь длится 2 часа.
- Часы работы и статус «Открыто / Закрыто» — из базы, по московскому времени.
- В шапке «Войти» / «Кабинет» / «Админка» и корзина со счётчиком. Вошедшему гостю имя
  и телефон подставляются в бронь и в заказ.

**Личный кабинет (`/account`)** — свои брони (отмена не позже чем за час до начала),
свои заказы со статусом (обновляется сам) и кнопкой «Повторить» (позиции из стоп-листа
не добавляются, об этом пишем), профиль и смена пароля.

**Админка (`/admin`)**

- «Сегодня»: брони на сегодня, заказы в работе, сколько гостей ждём, выручка по выданным
  заказам за сегодня и за 7 дней.
- Доска заказов: новый → принят → готов → выдан, отменён. Обновляется раз в 20 секунд,
  на телефоне колонки — вкладки.
- Брони по дням: подтвердить, «гости пришли», завершить, отменить, «не пришли»;
  пересадить за другой свободный столик.
- Меню: стоп-лист в один клик, добавить, изменить, скрыть. Позицию, которую уже заказывали,
  удалить нельзя — только скрыть.
- Столики (схема зала карточками по зонам), часы работы по дням недели, роли пользователей.

Необязательно: уведомления о новых бронях и заказах в Telegram (`TELEGRAM_BOT_TOKEN`,
`TELEGRAM_CHAT_ID`). Таймаут 3 секунды; если Telegram не ответил, бронь или заказ всё равно сохраняются.

## Стек

| Слой | Технологии |
| --- | --- |
| Сайт | статичный HTML/CSS/JS из `public/` (GSAP и Lenis — как в исходном лендинге) |
| Кабинет и админка | React 19, React Router 7, Vite 7, свой CSS без UI-библиотек |
| Сервер | PHP 8.4 без фреймворка, PDO и подготовленные запросы |
| База | MySQL 8, InnoDB, utf8mb4 |
| Деплой | Docker → Render (free), база в Aiven MySQL (free) |

```
│   ├── app.css        стили корзины, кнопок «+», метки стоп-листа, входа в шапке
│   ├── app.js         корзина и заказ с собой, вход в шапке, подстановка имени и телефона

├── database/          001-schema.sql, 002-cafe-data.sql, migrate.php, seed-demo.php, create-admin.php

├── Dockerfile, start.sh, router.php
```

Главные решения:

- **Один столик не займут дважды.** Бронь создаётся в транзакции: подходящие столики читаются
  с `SELECT … FOR UPDATE`, поэтому две одновременные брони проверяются по очереди.
- **Цены считает сервер.** Браузер присылает только id позиций и количество. В `order_items`
  хранится снимок названия и цены: правка меню не меняет старые заказы.
- **Стоп-лист проверяется на сервере** (`FOR SHARE` на позиции во время оформления заказа).
- **Права — на сервере.** Кабинет отдаёт только записи с `user_id` вошедшего; чужая бронь
  для клиента «не найдена». Всё под `/api/admin/` — только для роли `admin`. Роль при регистрации
  от браузера не принимается.
- Пароли — bcrypt; сессия в cookie `penka_session` (HttpOnly, SameSite=Lax, Secure на HTTPS);
  лимит входа: 5 неудачных попыток на email + IP и 20 на IP за 15 минут; изменения принимаются
  только в JSON (иначе 415).
- Журнал `status_events`: кто и когда сменил статус брони или заказа.

## Демо-режим

`DEMO_MODE=1` — публичное демо: логины показываются на странице входа, в админке можно
двигать заказы и брони по статусам, пересаживать гостей и вести стоп-лист, а цены, состав меню,
столики, часы и роли менять нельзя (сервер отвечает 403). Профиль и пароль общих демо-аккаунтов
не меняются. `RESET_DEMO=1` — при каждом запуске пересоздавать демо-данные: меню, 7 столиков,
брони и заказы за прошлую неделю, сегодня и ближайшие дни. Все гости и телефоны в них вымышленные.

| Роль | Email | Пароль |
| --- | --- | --- |
| Гость (кабинет) | `demo@penka.local` | `PenkaDemo2026` |
| Бариста (админка) | `admin@penka.local` | `PenkaAdmin2026` |

## Запуск локально

Нужны PHP 8.4+ с `pdo_mysql`, MySQL 8 и Node.js 20.19+ с npm.

```bash
# 1. Настройки: впишите пользователя и пароль MySQL. Базу penka migrate.php создаст сам
#    (нужно право CREATE на неё). APP_ENV=development разрешает демо-данные.
cp .env.example .env

# 2. Таблицы, меню, столики, часы и демо-данные
php database/migrate.php
php database/seed-demo.php

# 3. Кабинет и админка
npm install
npm run build

# 4. Сервер
php -S 127.0.0.1:8092 -t public router.php
```

Сайт — http://127.0.0.1:8092, вход — http://127.0.0.1:8092/login.
Для правки React удобнее `npm run dev` (Vite на порту 5182, запросы `/api` уходят на 8092),
тогда вход открывается по адресу http://127.0.0.1:5182/login.

Свой администратор: `php database/create-admin.php you@example.com "пароль-от-8-символов" "Имя"`.

## Деплой: Render + Aiven

Сервис `penka` уже описан в корневом [`render.yaml`](../../render.yaml) (Docker, бесплатный план,
`rootDir: apps/penka`, проверка `/api/health`).

1. В Aiven создайте бесплатный MySQL, скопируйте **Service URI** и скачайте **CA certificate**.
2. В Render: **New → Blueprint** → репозиторий. Для `penka` введите `DATABASE_URL` (Service URI)
   и `DB_SSL_CA` (текст `ca.pem` целиком). Остальное (`DB_NAME=penka`, `DEMO_MODE=1`,
   `RESET_DEMO=1`, `SESSION_SECURE=1`, `TRUST_PROXY=1`) уже в `render.yaml`.
3. При запуске `start.sh` поднимает сервер, создаёт базу `penka` на том же сервере Aiven
   (`CREATE DATABASE IF NOT EXISTS`), выполняет миграции и пересоздаёт демо-данные.

Бесплатный сервис Render засыпает без посетителей: первый заход после паузы открывается
около минуты.
