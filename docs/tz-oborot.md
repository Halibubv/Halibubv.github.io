# ТЗ: ОБОРОТ — веб-приложение автосервиса

Версия 1.0 · 27.11.2026 · демо-проект для портфолио (компания вымышленная)

## 1. Цель

Сейчас ОБОРОТ — статичный лендинг (`/oborot/`): калькулятор цены и форма записи, которая никуда не отправляется.
Нужно сделать из него полноценное веб-приложение уровня ВИНЛАНД: запись на сервис сохраняется в базе,
у клиента есть личный кабинет, у сервиса — админка для работы с записями и прайсом.

Что показываем будущему заказчику: «вот так у вас будут приходить и обрабатываться записи».

## 2. Роли

| Роль | Кто | Что может |
|---|---|---|
| Гость | любой посетитель | смотреть сайт, считать цену, записаться без регистрации (имя + телефон) |
| Клиент | зарегистрированный | всё, что гость, + кабинет: свои машины, свои записи, отмена, профиль |
| Администратор | сотрудник сервиса | админка: записи, расписание, прайс, клиенты, настройки |

## 3. Публичная часть (лендинг)

Вёрстка и стиль берутся из текущего лендинга `oborot/index.html` (после правок треда с картинками).
Меняется только поведение:

1. **Прайс из базы.** Услуги, цены, длительность, коэффициенты кузова и список премиум-марок приходят из `GET /api/catalog`.
   Если API недоступно, показываем сообщение «Не удалось загрузить прайс» вместо пустого калькулятора.
2. **Свободное время из базы.** Слоты на 14 дней вперёд приходят из `GET /api/slots?date=ГГГГ-ММ-ДД&hours=N`.
   Слот занят, если на всё время работ (N часов от начала) свободных постов нет. Прошедшее время недоступно.
3. **Запись сохраняется.** `POST /api/bookings`: марка, кузов, услуги, дата, время, имя, телефон, комментарий,
   необязательно — машина из гаража клиента. Цену и длительность **считает сервер** по тем же правилам, что калькулятор,
   цифрам из браузера не доверяем. Ответ: номер записи и итог.
4. **Шапка.** Кнопка «Войти» (гость) или «Кабинет» (клиент) / «Админка» (администратор).
5. Если клиент вошёл, имя и телефон в форме подставляются, а в форме появляется выбор машины из гаража.

### Правила расчёта (как в текущем калькуляторе)
- цена услуги = базовая цена × коэффициент кузова (седан 1, кроссовер 1,2, внедорожник 1,4) × 1,15 для премиум-марки,
  округление до 50 ₽;
- от 3 услуг — скидка 10 % на сумму, округление до 50 ₽;
- длительность = сумма часов услуг × 1,15, если кузов не седан; в слотах округляем вверх до целого часа.

### Расписание
- работаем ежедневно 9:00–21:00, слоты по часу с 9:00 до 20:00; работа должна закончиться до закрытия;
- число постов (по умолчанию 4) и часы работы задаются в настройках админки;
- запись занимает пост на всю длительность; одновременно — не больше записей, чем постов;
- проверка занятости выполняется в транзакции с блокировкой, чтобы два клиента не заняли последний пост одновременно.

## 4. Регистрация и вход

- Регистрация: имя, email, телефон, пароль (от 8 символов). Вход: email + пароль. Выход.
- Пароли — `password_hash` (bcrypt). Сессия PHP в cookie HttpOnly, SameSite=Lax, Secure на HTTPS.
- Лимит входа: 5 неудачных попыток на пару email + IP и 20 на IP за 15 минут (как в ВИНЛАНД).
- Все запросы на изменение — только JSON (`Content-Type: application/json`), иначе 415: защита от CSRF вместе с SameSite.

## 5. Личный кабинет клиента (`/account`)

1. **Мои записи.** Ближайшие и прошлые: дата, время, машина, услуги, сумма, статус.
   Отменить можно запись в статусе «новая» или «подтверждена» не позже чем за 2 часа до начала.
2. **Гараж.** Список машин: марка, модель, кузов, год, госномер (необязателен). Добавить, изменить, удалить.
   Машину с будущими записями удалить нельзя.
3. **Профиль.** Имя, телефон, смена пароля (нужен текущий пароль).
4. Пустые состояния с кнопкой «Записаться» / «Добавить машину».

## 6. Админка (`/admin`)

1. **Сводка.** Записи на сегодня (по времени), число новых неподтверждённых, загрузка постов на сегодня и завтра,
   сумма по выполненным записям за 7 дней. Все цифры считаются из базы, ничего не придумываем.
2. **Записи.** Таблица с фильтрами: дата (от–до), статус, поиск по имени/телефону. Карточка записи: клиент, машина,
   услуги и цены на момент записи, комментарий, история смены статуса.
   Статусы: `new` новая → `confirmed` подтверждена → `in_work` в работе → `done` выполнена; `cancelled` отменена,
   `no_show` не приехал. Переходы только допустимые.
3. **Расписание.** День по постам: сетка «время × пост» с записями, переключение дня.
4. **Прайс.** Услуги: название, описание, базовая цена, часы, порядок, активна/скрыта. Добавить, изменить, скрыть.
   Удалять услуги, которые есть в записях, нельзя, только скрывать. Прошлые записи хранят цену на момент записи.
5. **Клиенты.** Список: имя, email, телефон, число записей, последняя запись.
6. **Настройки.** Число постов, часы работы, марки (премиум или нет).

## 7. Данные (MySQL 8, utf8mb4)

| Таблица | Поля (основные) |
|---|---|
| `users` | id, email (уникальный), password_hash, name, phone, role (`client`/`admin`), created_at |
| `login_attempts` | email, ip, attempted_at |
| `cars` | id, user_id → users, brand, model, body (`sedan`/`cross`/`suv`), year, plate |
| `services` | id, code, name, description, base_price, hours, sort, is_active |
| `brands` | id, name, is_premium, sort |
| `settings` | key, value (posts, open_hour, close_hour) |
| `bookings` | id, user_id (null у гостя), car_id (null), brand, body, starts_at, ends_at, customer_name, phone, comment, total, discount, status, created_at |
| `booking_items` | booking_id → bookings, service_id, name, price, hours (снимок на момент записи) |
| `booking_events` | booking_id, status, user_id (кто сменил), created_at |

Миграции — файлы `database/NNN-*.sql`, выполняются `database/migrate.php` при старте контейнера.

## 8. Демо-режим (`DEMO_MODE=1`)

- При старте (`RESET_DEMO=1`) создаются демо-аккаунты клиента и администратора и записи на ближайшие дни
  с пометкой, что данные демонстрационные. Логины и пароли показываются на странице входа.
- В админке на демо можно менять статусы записей (это безопасно), но нельзя менять прайс, марки, настройки и роли (403).
- Отзывов, рейтингов и «довольных клиентов» на сайте нет: не выдумываем.

## 9. Уведомления (необязательно)

Если заданы `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`, о новой записи приходит сообщение в Telegram.
Без них приложение работает так же, просто без уведомлений. Ошибка Telegram не ломает запись.

## 10. Технологии и деплой

- Сервер: PHP 8.4 без фреймворка, PDO + подготовленные запросы, MySQL 8.
- Кабинет и админка: React 19 + React Router 7 + Vite, без UI-библиотек, в стиле лендинга
  (бумага, красный, Oswald + Manrope + JetBrains Mono).
- Лендинг — статичный HTML в `public/`, отдаётся на `/`; кабинет и админка — сборка Vite в `public/ui`.
- Docker: Node собирает интерфейс → образ `php:8.4-cli` с `pdo_mysql`. Хостинг Render (free), база Aiven MySQL (free),
  `DATABASE_URL` + `DB_NAME=oborot`. Blueprint — общий `render.yaml` в корне репозитория.
- Адаптив: 1280 / 834 / 390 px. Без бегущей строки, кастомного курсора и 3D-наклона карточек.

## 11. Готово, когда

- [ ] Запись с лендинга появляется в админке и (если клиент вошёл) в кабинете.
- [ ] Занятые слоты не предлагаются, двойная запись на последний пост невозможна.
- [ ] Цена в записи совпадает с калькулятором и считается сервером.
- [ ] Клиент видит только свои записи и машины (проверка владельца на сервере).
- [ ] Админка недоступна клиенту (403), кабинет — гостю (401).
- [ ] Работает на телефоне 390 px.
- [ ] Приложение собирается в Docker и запускается с пустой базой (миграции + демо-данные).
