# ТЗ: Пенка — веб-приложение кофейни

Версия 1.0 · 27.11.2026 · демо-проект для портфолио (кофейня вымышленная)

## 1. Цель

Сейчас Пенка — статичный лендинг (`/penka/`): меню, форма брони столика, которая никуда не отправляется, часы и схема проезда.
Нужно сделать полноценное веб-приложение уровня ВИНЛАНД: бронь столиков и заказы с собой сохраняются в базе,
у гостя есть личный кабинет, у кофейни — админка: брони, заказы, меню со стоп-листом, столики.

Что показываем будущему заказчику: «гости бронируют и заказывают сами, вы видите всё в одном окне».

## 2. Роли

| Роль | Кто | Что может |
|---|---|---|
| Гость | любой посетитель | смотреть меню, забронировать столик и заказать с собой без регистрации (имя + телефон) |
| Клиент | зарегистрированный | всё, что гость, + кабинет: свои брони и заказы, повтор заказа, профиль |
| Администратор | бариста / управляющий | админка: брони, заказы, меню, столики, часы работы |

## 3. Публичная часть (лендинг)

Вёрстка и стиль — из текущего `penka/index.html` (после правок треда с картинками). Меняется поведение:

1. **Меню из базы.** `GET /api/menu`: категории (Кофе, Не кофе, Завтраки, Выпечка) и позиции: название, описание, цена,
   объём/вес, метки (хит, веган), признак «нет в наличии». Позиции в стоп-листе видны, но помечены и не добавляются в заказ.
2. **Заказ с собой.** У позиции кнопка «+». Корзина — выезжающая панель: количество, сумма, время готовности
   (не раньше чем через 15 минут, в часы работы, шаг 15 минут), имя, телефон, комментарий.
   `POST /api/orders`. Цены считает сервер. Оплата при получении (онлайн-оплаты нет, это честно пишем).
   Корзина хранится в `localStorage` до отправки.
3. **Бронь столика.** День (14 дней вперёд), время (каждые 30 минут; последняя бронь за 1,5 часа до закрытия),
   гостей 1–8, пожелания. Свободное время приходит из `GET /api/slots?date=…&guests=N`.
   `POST /api/reservations`: сервер сам подбирает самый маленький свободный столик, куда помещаются гости.
   Бронь длится 2 часа. Проверка в транзакции с блокировкой: один столик нельзя занять дважды.
4. **Часы работы и статус «Открыто/Закрыто»** — из `GET /api/hours`.
5. **Шапка:** «Войти» / «Кабинет» / «Админка». Если клиент вошёл, имя и телефон подставляются.

## 4. Регистрация и вход

Как в ВИНЛАНД и ОБОРОТ: имя, email, телефон, пароль от 8 символов; bcrypt; сессия HttpOnly + SameSite=Lax;
лимит 5 попыток на email + IP и 20 на IP за 15 минут; изменения только JSON.

## 5. Личный кабинет (`/account`)

1. **Брони.** Ближайшие и прошлые: дата, время, гостей, зона столика, статус. Отмена — не позже чем за 1 час.
2. **Заказы.** Номер, состав, сумма, время готовности, статус. Кнопка «Повторить»: позиции попадают в корзину
   (кроме тех, что сейчас в стоп-листе, о них пишем).
3. **Профиль.** Имя, телефон, смена пароля.

## 6. Админка (`/admin`)

1. **Сегодня.** Брони на сегодня по времени, активные заказы, число гостей, ожидаемых сегодня, выручка по выданным заказам
   за сегодня и за 7 дней. Все цифры из базы.
2. **Заказы.** Доска по колонкам: `new` новый → `accepted` принят → `ready` готов → `issued` выдан; `cancelled` отменён.
   Карточка: номер, имя, телефон, состав, время готовности. Кнопки перевода в следующий статус. Обновление списка раз в 20 секунд.
3. **Брони.** Список по дню: время, гости, столик, имя, телефон, пожелания. Статусы: `new` новая → `confirmed` подтверждена →
   `seated` пришли → `closed` завершена; `cancelled` отменена, `no_show` не пришли. Можно пересадить за другой свободный столик.
4. **Меню.** Позиции по категориям: название, описание, цена, объём, метки, порядок. Переключатель «в наличии / стоп-лист»
   в один клик. Добавить, изменить, скрыть. Удалять позиции, которые есть в заказах, нельзя — только скрывать.
5. **Столики.** Номер, вместимость, зона (у окна / диван / большой стол), активен. Схема зала — простая сетка карточек.
6. **Часы работы** по дням недели.

## 7. Данные (MySQL 8, utf8mb4)

| Таблица | Поля (основные) |
|---|---|
| `users` | id, email, password_hash, name, phone, role (`client`/`admin`), created_at |
| `login_attempts` | email, ip, attempted_at |
| `categories` | id, code, name, sort |
| `menu_items` | id, category_id, name, description, price, size, tags, is_available, is_hidden, sort |
| `cafe_tables` | id, label, seats, zone, is_active |
| `opening_hours` | weekday (0–6), opens, closes |
| `reservations` | id, user_id (null у гостя), table_id, starts_at, ends_at, guests, customer_name, phone, comment, status, created_at |
| `orders` | id, user_id (null), customer_name, phone, comment, ready_at, total, status, created_at |
| `order_items` | order_id, menu_item_id, name, price, qty (снимок на момент заказа) |
| `status_events` | entity (`order`/`reservation`), entity_id, status, user_id, created_at |

## 8. Демо-режим (`DEMO_MODE=1`)

- `RESET_DEMO=1`: при старте пересоздаются демо-аккаунты (клиент и администратор), меню, столики (7 столиков на 2–6 мест)
  и несколько броней и заказов на сегодня и ближайшие дни. Логины показываются на странице входа.
- На демо в админке можно двигать заказы и брони по статусам и переключать стоп-лист,
  но нельзя менять цены, состав меню, столики, часы работы и роли (403).
- Никаких отзывов, рейтингов и «тысяч чашек в день».

## 9. Уведомления (необязательно)

`TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHAT_ID` — сообщение о новой брони и новом заказе. Без них всё работает.

## 10. Технологии и деплой

- PHP 8.4 без фреймворка + MySQL 8, как в ВИНЛАНД и ОБОРОТ.
- Кабинет и админка: React 19 + React Router 7 + Vite, без UI-библиотек, в стиле лендинга
  (кремовый фон, терракота, Fraunces + Manrope, мягкие скругления). На ОБОРОТ не похоже.
- Лендинг — статичный HTML в `public/` на `/`, кабинет и админка — сборка Vite в `public/ui`.
- Docker → Render (free), Aiven MySQL (free) с `DB_NAME=penka`. Общий `render.yaml` в корне репозитория.
- Адаптив: 1280 / 834 / 390 px. Без бегущей строки, кастомного курсора и 3D-наклона карточек.

## 11. Готово, когда

- [ ] Бронь с лендинга появляется в админке; занятый столик второй раз не отдаётся.
- [ ] Заказ с собой появляется на доске заказов, статус виден клиенту в кабинете.
- [ ] Стоп-лист сразу отражается в меню на сайте; такую позицию нельзя заказать (проверка на сервере).
- [ ] Клиент видит только свои брони и заказы; админка — только администратору.
- [ ] Работает на телефоне 390 px.
- [ ] Собирается в Docker и стартует с пустой базой (миграции + демо-данные).
